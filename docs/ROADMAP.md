## 既知の課題（記録）

### 1. 二次テキストのコントラスト ✅ 解決済み（2026-08-30）

`neutral2` に文字専用の1段 **`500 = #5C697D`** を追加し、`text-neutral2-300` の
**47か所（14ファイル）を `text-neutral2-500` へ差し替えた。**

| | |
|---|---|
| 実測（変更後） | 白 **5.57** ／ main-50 5.25 ／ main-100 5.04 ／ **main-200 4.54（最小）** ／ crystal-100 5.01 ／ crystal-200 4.62 ／ crystal-300 5.00 ／ neutral2-100 4.97 |
| 判定 | 背景8種すべてで **AA 4.5:1 以上＝不合格 0件**（対象は 9〜14px の小さい文字のみ＝大文字例外なし） |
| 文字階層 | `ink 15.21` ＞ `neutral2-500 5.57` ＞ `neutral2-300 1.41`。主要文字（`ink`・51か所）は未変更のため階層は維持 |
| 変更しなかったもの | `main` / `crystal` / `accent` / `neutral2` 既存4段 / `ink`、`bg-neutral2-100`（3か所）、`border-neutral2-200`（11か所）＝**面・背景・枠線は不変** |
| 検証 | `tsc -b --force` エラー0 ／ `npm run build` 成功 |

> ⚠️ **Figma より実装が先行している例外。`neutral2.500` は Figma 側に存在しない。**
> 通常このプロジェクトは Figma を色の正本とするが、この1段だけは**実装が先**にある。
> **Figma 側は未反映・同期待ち。** Figma に二次テキスト用の段を追加して同期させるまで、この状態が続く。
> 同期の際は `#5C697D`（H=216.4 / S=15.2% / L=42.5%）をそのまま入れれば実装と一致する。

**経緯（履歴・書き換えない）**
- v0.18 の「やっていないこと」に `neutral2-300 の色変更` と明記＝長く既知の未対応だった
- 2026-08-30 当初の判断は「**Figma が色の正本のため一括置換しない**」（着手条件＝Figma 側で色が確定すること）
- 当時の最小案（未承認・参考）は `neutral2` に **400番（例 `#8A9099` 前後）** を足す形だった
- 同日、**着手条件を外す判断**へ変更。理由 — この1点が v0.19 を止めている唯一の要因であり、
  面カラーを一切変えず「文字用の1段を足すだけ」なら Figma の面設計と競合しないため
- 実際に採用したのは **`500 = #5C697D`**（当時の案の `400 = #8A9099` とは別の値。8種の背景すべてで AA を満たす値として算出し直した）
