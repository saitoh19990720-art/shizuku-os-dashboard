## 1. 作品名
**Shizuku OS Dashboard v0.19**

## 2. 一言説明
AIの速さを、人間の判断で仕事品質へ戻す制作OS。

## 3. 背景
AIで案・文章・UI・コードは大量に出せるようになった。
でも本当に重いのは「どれを採用するか／なぜ使えるか／安全か／次にどう進めるか」。
その**判断と再開**を支えるために作った、個人用の制作ダッシュボード。

## 4. 作ったもの（v0.19・現在の姿）

**2画面**：Landing（作品紹介）／ Dashboard（実物）。依存を足さない軽量ハッシュルーティング（`/` ↔ `#/dashboard`）で切り替える。

**Dashboard は12カードを1画面に縦積み**（App.tsx の並び順）：

| # | カード | 役割 |
|---|---|---|
| 1 | 今日のコンディション | 体力・痛み・制作モード・休憩条件。機微情報のためJSONバックアップから除外 |
| 2 | 今日の次アクション | 迷った時の「これ1つ」を上部に固定・完了チェック |
| 3 | 今日の制作候補 | 優先度（高/中/低）×状態（今日/明日/保留）で管理 |
| 4 | AI Role Router | タスク種別 → どのAIに投げるかの早見 |
| 5 | Prompt Builder（＋Vault） | 目的・制約・出力形式・やらないこと → プロンプト生成。保存・絞り込み・再コピー |
| 6 | 夜タスク3行ログ | やった／学び／次やる を1日分として記録 |
| 7 | 制作中リンク | Figma・GitHub・メモ・参考URL。URLは「開く」リンクに |
| 8 | **Quality Gate** | 採用／保留／捨てる を4観点で判定。履歴保存・Obsidian用Markdown出力・判定で絞り込み |
| 9 | Weekly Review | 週次の やった/学び/次/来週の重点。Obsidian用Markdownでコピー |
| 10 | Brand Panel | 冷色トークン・フォント・世界観キーワードを表示 |
| 11 | n8n Bridge（JSON入出力） | 全データをJSONでコピー／ダウンロード／読み込み。**外部送信なし** |
| 12 | 今日はここまででOK（Retire OK） | 状態・止める理由・再開地点・次の一手を残して安全に区切る |

**共通の土台**：カードの折りたたみ（開閉状態も保存）／localStorage 保存（外部送信なし・保存失敗は画面上部に警告）／空状態メッセージ／320px まで破綻しない1カラム（最大400px程度）。

## 5. 技術
React 18 / TypeScript（strict）/ Tailwind CSS / Vite / localStorage / Vercel
外部ライブラリは**react・react-dom のみ**（ルーターもUIキットも入れていない）。

## 6. ポートフォリオで説明価値の高い改善（v0.18→v0.19・PR #1〜#9）

> どれも「機能を足した話」ではなく、**すでにある機能を仕事品質へ上げた話**。面接で説明しやすい順に並べた。

### 6-1. 320px までのレスポンシブ（PR #3）
- 症状：制作中リンクカードで、ラベル入力欄が縮まず追加ボタンが押し出され、**320px で横スクロールが発生**していた。
- 対応：入力欄が縮めるようにする1行の修正（`LinksCard.tsx`）。他カード・保存・文言には触っていない。
- 検証：320 / 390 / 1440px で横方向のはみ出しなし。追加・削除の動作とコンソールエラー無しまで確認。
- 説明の芯：**一番狭い端末を「対応済み」と言い切れる状態にした**。修正量より、壊れる幅を先に決めていることが要点。

### 6-2. WCAG AA コントラスト改善（PR #4）
- 症状：二次テキスト（`neutral2-300`）が本文コントラスト 4.5:1 に届いていなかった。
- 対応：Tailwind に**文字専用の1段 `neutral2.500 = #5C697D`** を追加し、該当 **47か所（14ファイル）** を差し替え。
- 実測：背景8種すべてで AA 達成（白 5.57 ／ 最小 main-200 で **4.54**）。**不合格0件**。
- 壊さなかったもの：面・背景・枠線の色は不変。主要文字 `ink`（15.21）は未変更なので**文字の階層は維持**。
- 制約下の判断：色の正本は Figma。ここは**「文字用の1段を足すだけなら面設計と競合しない」と判断して実装を先行**させた例外で、Figma 側は同期待ち（`#5C697D` をそのまま入れれば一致する）。
- 説明の芯：**数値で合否を出し、変えない範囲を先に線引きした**アクセシビリティ改善。

### 6-3. localStorage / JSON import の安全策（PR #1・#2）
- **保存失敗を黙って捨てない**：容量超過やプライベートモードで書けなかったキーを記録し、画面上部に警告（`StorageAlert`）。書き直せたら警告は消える。
- **読み込みは検証してから**：JSON インポート時に各カードの形式を検証し、合わなければ**保存も再読み込みもせず中止**（例：リンクの `url` 必須）。
- **途中で失敗したら元に戻す**：書き込み前に元の文字列を退避し、失敗時はロールバック。未保存だったキーは削除して元の状態へ戻す。戻すことにも失敗した場合だけ、その旨を明示する。
- **機微情報は持ち出さない**：今日のコンディション（体調）は**意図的にバックアップ対象外**。
- 説明の芯：**外部送信ゼロのローカルアプリでも、データを失う経路を潰す設計をしている**。

### 6-4. Quality Gate（作品の核・v0.2〜v0.4で実装、現在も中核）
- 案・制作物を **部下視点／消費者視点／勝算／安全** の4観点（各3項目＋次の一手）で見て、**採用／保留／捨てる**を決める。
- 判定は履歴に保存でき、Obsidian 用 Markdown（frontmatter 付き）でコピー、判定で絞り込みもできる。
- 説明の芯：これがあるので「タスク管理アプリ」ではなく**制作OS**になる。**AI案を無審査で通さない仕組みを、UIとして実装した**。

### 6-5. typecheck / build（PR #5）
- `npm run typecheck`（`tsc --noEmit`）を追加。既存の `tsconfig`（`strict: true`）をそのまま使い、パッケージ追加ゼロ・`build` script も未変更（Vercel の経路に影響なし）。
- 現在の状態：**`npm run typecheck` PASS（2026-09-01 実行・エラー0）**。本番は `npm run build`（`tsc -b && vite build`）。
- 説明の芯：**「動いた」ではなく「再現できる形で確認した」に変えた**1行。

### 6-6. Codex レビュー（PR #1・#3〜#9）
- PR を開くと Codex の自動レビューが走る設定。実際に**指摘が実装につながった**例が 6-1（`codex/fix-links-card-320-overflow` ブランチ）。
- PR #2 は、マージ後レビューで出た storage 周りの指摘をまとめて潰したもの。
- 説明の芯：**AIレビューを「感想」ではなく差分として取り込むフローを回している**。Claude が実装 → Codex が粗探し → 本人が採否、の三者分業。

### 6-7. 表記と実装のズレを潰した（PR #7）
- 「スマホ幅（360px前後）」と書いていたが、**360px は要件ではなく監査で使った測定用ビューポート**だった。実装事実（`max-w-[400px]`・320px対応）に表記を直した。
- 「公開中 v0.18／ローカル v0.19（未デプロイ）」も、公開URLで配信中のCSSに v0.19 の文字色 `#5C697D` があることを実測して訂正。
- 説明の芯：**ドキュメントを実測で検証し、盛らずに直せる**。ポートフォリオでは地味だが、実務での信用に直結する。

## 7. AIに任せたこと／人間が判断したこと

> この作品は「AIで作った」ではなく「**AIを編成して作った**」。面接で聞かれたらここを話す。

| | AI（Claude Code / Codex）に任せた | しずく（人間）が決めた |
|---|---|---|
| 設計 | 実装案の列挙・影響範囲の洗い出し | 何を作るか。中核3価値（迷わず戻れる／雑案を通さない／速さを品質へ）。Figma での情報設計 |
| 実装 | コード差分・型・PR文面・変更履歴の整合 | どのカードを足し、どこで止めるか（12カードで機能追加を止める判断） |
| デザイン | AA を満たす色値の算出（`#5C697D`）と47か所の差し替え | 色の正本は Figma という原則。**その例外を1段だけ認める**判断と、面・枠線は触らせない線引き |
| 検証 | typecheck / build の実行、コントラスト実測、320/390/1440px の確認、Codex の自動レビュー | 指摘を採用するか・今直すか（PR #2・#3 は採用、Figma同期は保留） |
| 公開 | ブランチ・PR・差分の用意 | **マージと公開のタイミングは全て本人**。スクリーンショットの採否も本人 |
| 安全 | 機微データの扱いを実装に落とす | 体調カードをバックアップから外す判断。外部API・n8n本接続を**今はしない**判断 |

合言葉：**AIは速さと整理。採用・方向・公開の最終判断は人間。**

## 9. 次に改善するなら（ROADMAP の採用順）

1. **テスト基盤（Vitest）** — 構造変更の前に保険をかける
2. **データを `projectId` で串刺しにする** — 6構造化の前提
3. **12カード → 6構造へ畳む**（North Star / Current / Bottleneck / Decisions / AI Office / Resume）
   ※ **機能を足さずに畳む**。作品の主張＝「複雑を静かに構造化」の実証にあたる
4. **Bottleneck カード**（詰まっていること・判断待ち）

保留：meta description / OGP / favicon、横断 Search / Filter、AI夜勤キュー（**自動実行にはしない**）。
→ 詳細と判定は [`docs/ROADMAP.md`](./ROADMAP.md)。
